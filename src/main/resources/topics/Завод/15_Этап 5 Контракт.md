# Этап 5. Заказчик ждёт

Завод производит пластины, но заработать галочку «выполнено» пока не может. Реализуй `submit(Inventory warehouse, int tick)` в `student/Contract.java`.

Конструктор уже сохраняет `target` и `deadline`. Используй **эти поля**, а не числа 40 и 100 внутри метода. Игровая смена создаёт именно такой заказ, но сам класс должен работать и с другими положительными параметрами.

## Реализация

Сначала откажи, если заказ выполнен, время отрицательное, срок прошёл или склад отсутствует. Затем попробуй выдать `target` пластин через `warehouse.remove`. При отказе верни `false`. При успехе запомни завершение и верни `true`.

Не вычитай пластины вручную и не создавай новый склад. Не выставляй `complete` до успешного списания. Именно готовый `Inventory` защищает от частичной выдачи.

## Проверка кода и всей линии

Запусти `./mvnw -Pstage-5 test` или `.\mvnw.cmd -Pstage-5 test`. Здесь есть проверки отдельного контракта и полного завода. Затем выполни `./mvnw -Pall-stages test` — теперь должны пройти **все** этапы на твоём коде.

В браузере перезапусти обычное приложение и выбери «Новая смена» → «Контракт». Получишь стартовые шахту, плавильню, склад и 300 кредитов на стройку. Учебных поставок в этом режиме нет. На такте 100 часы остановятся; сдавать готовый заказ на этом такте ещё разрешено.

Построй линию пластин и попробуй выполнить заказ кнопкой «Сдать заказ». Пластины должны лежать именно на стартовом складе №3. На выходе пресса они ещё не доставлены. Если не успел, подумай, какой станок ограничивает выпуск. Следующая глава поможет посчитать.

Просрочка — `tick > deadline`, а не `tick >= deadline`. Проверку `warehouse == null` сделай до обращения к его методам. Вызов `remove(Resource.PLATE, target)` уже возвращает нужный результат выдачи.

На паузе построй пресс за 120 и вторую плавильню за 100. Удали начальную связь плавильня №2 → склад №3. Соедини шахту с обеими плавильнями, обе плавильни — с прессом, пресс — со складом №3. Начальная связь шахта → плавильня №2 уже есть. В бюджете останется 80.

Запускай: эта конфигурация успевает доставить не менее 40 пластин к такту 100. Увеличение скорости удобно для ожидания, но не меняет результат по тактам. На финише нажми «Сдать заказ» и проверь остатки на складе.

**Готово, когда:** все тесты проходят на твоём коде, заказ принимается вовремя и только один раз, а завод уложился в бюджет. Сохрани финальную версию проекта.

{collapsible="true"}
Разбор и полный файл решения
{/collapsible}

```java
package javapolis.factory.student;

import javapolis.factory.model.Resource;

/** Stage 5. Deliver 40 plates by tick 100, including the deadline tick itself. */
public final class Contract {
    private final int target;
    private final int deadline;
    private boolean complete;

    public Contract(int target, int deadline) {
        if (target <= 0 || deadline <= 0) throw new IllegalArgumentException("Некорректный контракт");
        this.target = target;
        this.deadline = deadline;
    }

    public int getTarget() { return target; }
    public int getDeadline() { return deadline; }
    public boolean isComplete() { return complete; }

    public boolean submit(Inventory warehouse, int tick) {
        if (complete || tick < 0 || tick > deadline || warehouse == null) return false;
        if (!warehouse.remove(Resource.PLATE, target)) return false;
        complete = true;
        return true;
    }
}
```

Сначала проверяются причины отказа. Склад выполняет целую выдачу, а флаг завершения защищает от повторного списания.
