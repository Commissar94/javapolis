# Этап 1. Склад без чёрной дыры

Прораб привёз руду. Склад ответил `false`. Таков пока весь производственный цикл. Исправим приёмку.

**Файл:** `src/main/java/javapolis/factory/student/Inventory.java`. Реализуй `add(Resource resource, int amount)` и `remove(Resource resource, int amount)`. Остальные методы готовы; используй `count`, `freeSpace` и поле `amounts`.

## Договорённости

| Запрос | Результат |
|---|---|
| `resource == null` или `amount <= 0` | `false`, ничего не меняется |
| Добавление больше свободного места | `false`, ничего не меняется |
| Выдача больше имеющегося количества | `false`, ничего не меняется |
| Корректное добавление | Количество растёт на `amount`, возвращается `true` |
| Корректная выдача | Количество уменьшается на `amount`, возвращается `true` |

Ограничение вместимости относится к сумме всех ресурсов. Выдача ровно всего запаса разрешена. Нулевые записи в карте можно оставить: `total()` от этого не меняется.

Не создавай новую карту при каждом вызове: объект должен помнить предыдущие поставки. `put` заменяет значение по ключу; чтобы увеличить запас, сначала узнай старое количество.

## Проверяем

В папке шаблона выполни `./mvnw -Pstage-1 test`. На Windows — `.\mvnw.cmd -Pstage-1 test`. В отчёте `Stage1InventoryTest` не должно быть ошибок. Прочитай названия тестов: там есть переполнение, общая вместимость и неизменность состояния после отказа.

Для ручной проверки вообрази склад на 10 мест: добавить 6 руды → добавить 3 слитка → попытаться добавить 2 пластины → выдать 2 руды. Последний результат: 4 руды, 3 слитка и 3 свободных места.

Перезапусти игру в обычном режиме. В песочнице выбери плавильню и нажми «Учебная поставка: +3 руды». Во входе станет 3. Восемь поставок заполнят вход на 24 места; девятая не изменит запас. Добыча и плавка пока ждут своих заданий.

Разбор и полный файл решения
{/collapsible}

```java
package javapolis.factory.student;

import javapolis.factory.model.Resource;
import java.util.EnumMap;
import java.util.Map;

/** Stage 1. The capacity is shared by ALL resource types. */
public final class Inventory {
    private final int capacity;
    private final Map<Resource, Integer> amounts = new EnumMap<>(Resource.class);

    public Inventory(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException("Вместимость должна быть положительной");
        this.capacity = capacity;
    }

    public int count(Resource resource) { return amounts.getOrDefault(resource, 0); }
    public int getCapacity() { return capacity; }

    public int total() {
        int sum = 0;
        for (int amount : amounts.values()) sum += amount;
        return sum;
    }

    public int freeSpace() { return capacity - total(); }
    public Map<Resource, Integer> snapshot() { return Map.copyOf(amounts); }

    public boolean add(Resource resource, int amount) {
        if (resource == null || amount <= 0 || amount > freeSpace()) return false;
        amounts.put(resource, count(resource) + amount);
        return true;
    }

    public boolean remove(Resource resource, int amount) {
        if (resource == null || amount <= 0 || amount > count(resource)) return false;
        amounts.put(resource, count(resource) - amount);
        return true;
    }
}
```

Проверки выполняются до изменения карты. Даже при большом запросе состояние остаётся прежним. `count` скрывает отсутствие записи за нулём.

{/collapsible}
