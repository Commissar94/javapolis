# Этап 4. Из слитков в пластины

Пора проверить, действительно ли предыдущий алгоритм был общим. В `student/Recipes.java` добавь рецепт для `MachineType.PRESS`: **3 слитка → 2 пластины за 3 рабочих такта**.

Сохрани рецепт плавильни: **1 руда → 1 слиток за 2 такта**. Для `MINE` и `WAREHOUSE` рецептов быть не должно. Меняется только каталог; `Processing` продолжает работать с переданным рецептом.

## Проверяем код

Запусти `./mvnw -Pstage-4 test` или `.\mvnw.cmd -Pstage-4 test`. Проверки используют уже написанные склад и обработку.

Подай прессу 6 слитков и вызови обработку 6 раз: получится 4 пластины, вход опустеет, прогресс станет 0. Если на выходе осталось только одно место, новая партия из двух пластин не начинается. Нельзя выпустить половину партии и списать все три слитка.

## Собираем линию

Перезапусти обычную игру, оставь её на паузе.

1. Построй пресс на свободной клетке между плавильней и складом. Он стоит 120 кредитов.
2. Выбери плавильню №2 и удали связь №2 → №3 крестиком в списке конвейеров.
3. Проведи конвейер от плавильни к прессу.
4. Выбери пресс и проведи конвейер к складу №3.
5. Запускай смену и наблюдай: сначала слитки копятся, затем пресс работает три такта и выпускает две пластины.

Один конвейер перевозит одну единицу за такт. Поэтому две пластины готовой партии могут приехать на склад в разные такты. Это нормально: выпуск и доставка — разные действия.

Не оставляй старую связь плавильня → склад: часть слитков уедет мимо пресса. Входящий конвейер от шахты к плавильне сохраняем.

{collapsible="true"}
Подсказка
{/collapsible}

У конструктора порядок аргументов такой: `Resource input, int inputAmount, Resource output, int outputAmount, int duration`. Для пресса вход — `INGOT`, выход — `PLATE`. Числа 3 и 2 обозначают размеры партии, последнее 3 — длительность.

{/collapsible}

**Готово, когда:** пластины приезжают на склад, у тебя один алгоритм обработки для двух типов станков, тесты зелёные. Сохрани версию «пресс».

{collapsible="true"}
Разбор и полный файл решения
{/collapsible}

```java
package javapolis.factory.student;

import javapolis.factory.model.MachineType;
import javapolis.factory.model.Recipe;
import javapolis.factory.model.Resource;
import java.util.Map;

/** Stage 4. Extend this catalogue; the processing algorithm should stay the same. */
public final class Recipes {
    private final Map<MachineType, Recipe> recipes = Map.of(
            MachineType.SMELTER, new Recipe(Resource.ORE, 1, Resource.INGOT, 1, 2),
            MachineType.PRESS, new Recipe(Resource.INGOT, 3, Resource.PLATE, 2, 3)
    );

    public Recipe forMachine(MachineType type) { return recipes.get(type); }
}
```

Различие между прессом и плавильней описано данными. Один рецепт не хранит прогресс всех станков — прогресс остаётся в `Machine`.
