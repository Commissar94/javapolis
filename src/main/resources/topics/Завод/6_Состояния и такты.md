# Состояния и такты

Шахта должна добывать руду постепенно. Если написать внутри неё бесконечный цикл, один вызов метода никогда не закончится. До плавильни очередь не дойдёт, а кнопка паузы будет смотреть на нас с укором.

Вместо этого метод `tick` выполняет **один шаг**. Готовый движок сам вызовет его снова, когда наступит следующий такт. Внутри шахты не нужны `while (true)`, `Thread.sleep` или новый поток.

## Порядок одного такта

1. Номер такта увеличивается на один.
2. Конвейеры переносят уже имеющуюся продукцию из выходов во входы получателей.
3. Шахты добывают, станки обрабатывают одну единицу времени.
4. Браузер получает очередное состояние.

Добытая на такте 1 руда уедет по конвейеру не раньше такта 2. Вход и выход у здания — разные склады: конвейер не может протащить новый ресурс через всю цепочку за один шаг.

Один конвейер переносит максимум одну единицу за такт, если она есть у источника и помещается у получателя. Несколько выходящих конвейеров по очереди получают первый шанс на ресурс. Геометрическая длина линии на карте в этой версии не влияет на скорость.

## Состояние — объяснение происходящего

У здания есть `enabled`, прогресс, запасы и статус. Статус нужен игроку, чтобы отличить проблему кода от обычной нехватки сырья.

| Статус | Почему здание не работает или работает |
|---|---|
| `PAUSED` | Игрок выключил здание |
| `OUTPUT_FULL` | Выпуск некуда положить |
| `NO_INPUT` | Не хватает сырья для партии |
| `WORKING` | Такт производства выполнен |
| `NO_RECIPE` | Для такого станка ещё нет рецепта |
| `TODO` | Учебный метод ещё не написан |

`READY` — начальное состояние. После первого вызова ты выставишь более точное. Выключение здания останавливает его производство; уже изготовленная продукция всё ещё может уехать по конвейеру.

## Такт — не секунда

При скорости 1× готовые часы пытаются выполнять один такт раз в 500 мс после предыдущего вызова. Это не гарантия точного реального времени. Для логики важен номер такта. Кнопка «Шаг» и JUnit могут продвигать те же правила без ожидания.

Spring Boot обслуживает запросы и таймер своими потоками, но готовый `FactoryEngine` последовательно допускает их к состоянию. Это инфраструктура шаблона. Ученические методы вызываются последовательно, и многопоточную модель мы здесь не проектируем.

**Проверь себя:** почему руда после первого «Шага» лежит на выходе шахты? Что должно произойти на втором? Почему увеличение скорости игры не должно менять число руды за 10 тактов?
