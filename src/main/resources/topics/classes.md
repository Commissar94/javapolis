# Классы и объекты

В Колизее у тебя были переменные героя. На заводе появятся несколько складов: у каждого своя вместимость и свои запасы. Если завести `ore1`, `ore2`, `ore3`, бухгалтер скоро убежит. Объединим данные и действия в класс.

## Чертёж и экземпляр

Класс описывает устройство объектов. Объект — конкретный экземпляр класса. Поля хранят его состояние, методы задают действия. Два склада одного класса могут содержать разное количество руды.

Сохрани весь пример в `Main.java` и запусти отдельно от игрового проекта:

```java
class OreBin {
    private final int capacity;
    private int ore;

    OreBin(int capacity) {
        this.capacity = capacity;
    }

    boolean addOne() {
        if (ore >= capacity) {
            return false;
        }
        ore++;
        return true;
    }

    int count() {
        return ore;
    }
}

public class Main {
    public static void main(String[] args) {
        OreBin first = new OreBin(2);
        OreBin second = new OreBin(5);
        first.addOne();
        System.out.println(first.count()); // 1
        System.out.println(second.count()); // 0
    }
}
```

`new OreBin(2)` создаёт объект и вызывает его конструктор. Конструктор называется как класс; у него нет возвращаемого типа, даже `void`. Число 2 попадает в параметр `capacity`. В `this.capacity = capacity` слева поле текущего объекта, справа параметр.

Поле `ore` получает начальное значение 0. У полей есть значения по умолчанию; локальную переменную внутри метода по-прежнему нужно инициализировать перед чтением. В примере предполагается положительная вместимость. Проверку неверных значений добавим в полноценный склад.

## К какому объекту обращаемся

Вызов `first.addOne()` меняет только первый склад. Здесь `addOne` — метод экземпляра, без `static`. `main` остаётся статическим: Java запускает его без создания объекта `Main`.

У статического поля одно значение на класс, а у обычного поля — своё значение в каждом экземпляре. Поэтому запасы станков не должны быть `static`: иначе две шахты начнут делить один счётчик.

`private` скрывает поля от прямого доступа из другого класса. В примере нельзя написать из `Main` выражение `first.ore = -100`. Работать со складом можно через его методы. В проекте публичные методы отмечены `public`, чтобы ими могли пользоваться классы из других пакетов. Методы без модификатора, как в коротком примере, доступны внутри своего пакета.

`final` у поля запрещает повторное присваивание после инициализации. Вместимость остаётся постоянной, а количество руды меняется. Это не означает, что весь объект стал неизменяемым.

## Файлы и пакеты

В проекте один публичный класс находится в одноимённом `.java`-файле. Строка `package javapolis.factory.student;` задаёт пакет, а `import` позволяет писать короткое имя класса из другого пакета. Это не скачивание библиотеки: зависимости проекта перечислены в `pom.xml`.

Не добавляй `main` в каждый склад. Точка входа приложения уже есть; она создаёт объекты и организует их работу.

**Проверь себя:** вызови `first.addOne()` три раза. Почему третий вызов вернул `false`, а `second.count()` остался равен нулю? Затем создай третий объект со своей вместимостью.
