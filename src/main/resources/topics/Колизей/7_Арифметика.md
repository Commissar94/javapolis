# Арифметика: меч встретился с бронёй

Паспорт готов, но здоровье пока умеет только красиво стоять в консоли. Научим его уменьшаться.

```java
int health = 100;
int damage = 13;
health = health - damage;
System.out.println(health); // 87
```

Сначала вычисляется правая часть, потом результат записывается слева. Это не математическое равенство `health = health - damage`, а команда изменения значения.

## Набор операций

| Оператор | Пример | Результат |
|---|---|---|
| `+` | `12 + 3` | `15` |
| `-` | `18 - 5` | `13` |
| `*` | `6 * 2` | `12` |
| `/` | `17 / 5` | `3` при целочисленном делении |
| `%` | `17 % 5` | `2`, остаток от деления |

Умножение и деление выполняются раньше сложения. Если порядок важен для понимания, используй скобки: `(attack + bonus) * 2`.

В нашей игре правило такое: `damage = attack - armor`. Если броня больше атаки, урон станет отрицательным и вычитание урона начнёт лечить противника. Броня, конечно, хорошая вещь, но медицинскую страховку мы ей не выдавали. Исправим это условием в следующей главе.

## Почему пропала дробная часть

```java
System.out.println(17 / 5);       // 3
System.out.println(17 / 5.0);     // 3.4
System.out.println((double) 17 / 5); // 3.4
```

При делении двух `int` результат тоже целый: дробная часть отбрасывается в сторону нуля. Поэтому `-17 / 5` даст `-3`. Запись `double result = 17 / 5;` не спасёт: деление уже произошло как целочисленное, а в переменную попадёт `3.0`.

`(double)` — явное преобразование типа. Обратное преобразование `(int) 3.9` даст `3`, `(int) -3.9` даст `-3` для этих значений. Это не округление к ближайшему целому. Чуть позже пригодится при генерации урона.

## Сокращения без фокусов

`health -= damage;` в нашем случае с `int` заменяет `health = health - damage;`. `wins++;` увеличивает счётчик на один, `potions--;` уменьшает. Пока используй `++` и `--` отдельными строками: их поведение внутри сложных выражений нам не нужно.

У `int` есть предел: переполнение не выдаёт автоматически ошибку. А целочисленное деление на ноль приводит к `ArithmeticException` во время работы. Здесь числа небольшие, делить на пользовательское значение мы не будем.

Практика: при атаке 18 и броне 5 посчитай урон 13, затем остаток здоровья от 45 — 32. Отдельно предскажи `17 % 5` и проверь запуском. `%` пригодится в будущих играх для правил вроде «каждый третий ход», но в обязательный бой пока не входит.
