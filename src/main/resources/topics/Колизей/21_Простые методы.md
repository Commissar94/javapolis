# Методы: назовём кусочек работы

Расчёт урона повторяется для героя и противника. Можно оставить две копии. Но если правило изменится, одну из них легко забыть. Выделим расчёт в метод.

```java
public class Main {
    public static void main(String[] args) {
        int damage = damageAfterArmor(18, 5);
        System.out.println(damage); // 13
    }

    static int damageAfterArmor(int attack, int armor) {
        return Math.max(1, attack - armor);
    }
}
```

Метод объявлен **внутри класса `Main`, но снаружи `main`**. Нельзя вставить его объявление внутрь другого метода. Расположение выше или ниже `main` для такого вызова не важно.

## Разбираем подпись

В `static int damageAfterArmor(int attack, int armor)`:

- `static` позволяет здесь вызывать метод через класс, без создания объекта `Main`.
- Первый `int` — тип результата.
- `damageAfterArmor` — имя метода.
- `attack` и `armor` — параметры, то есть имена входных значений внутри метода.
- `return` отдаёт результат вызывающему коду и завершает этот вызов.

Числа `18` и `5` в вызове — **аргументы**. Передали их, посчитали, получили `13`. Пока метод работает, выполнение `main` ждёт его результат, затем продолжается со следующей инструкции. Никаких потоков здесь нет.

Метод не запускается только потому, что объявлен. Его нужно вызвать. `println`, `Math.max`, `equals` мы уже вызывали; теперь написали один собственный.

## Когда результат не нужен

```java
public class Main {
    public static void main(String[] args) {
        printWelcome();
    }

    static void printWelcome() {
        System.out.println("Добро пожаловать на арену!");
    }
}
```

`void` означает отсутствие возвращаемого значения. Такой метод можно вызвать ради действия, но нельзя присвоить его результат в `int`. Печать в консоль и возврат значения — разные вещи: `damageAfterArmor` возвращает число, а не выводит его.

Не нужно превращать каждую строчку в отдельный метод. Хороший кандидат — понятное действие с именем: рассчитать урон, восстановить здоровье, прочитать команду.

Практика: вызови `damageAfterArmor(4, 99)` и получи 1. Затем `damageAfterArmor(18, 5)` и получи 13. Объясни, почему в самом методе нет имён `heroHealth` и `enemyHealth`: он не обязан знать, кто кого ударил.
