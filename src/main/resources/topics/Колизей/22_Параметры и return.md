# Вернуть здоровье — не значит поменять его везде

Примитивные аргументы передаются в метод **по значению**. Метод получает копию числа. Если внутри изменить параметр `health`, переменная вызывающего кода сама не изменится.

```java
public class Main {
    public static void main(String[] args) {
        int health = 50;
        restoreHealth(health, 20, 100);
        System.out.println(health); // всё ещё 50
        health = restoreHealth(health, 20, 100);
        System.out.println(health); // 70
    }

    static int restoreHealth(int health, int amount, int maxHealth) {
        return Math.min(maxHealth, health + amount);
    }
}
```

В первом вызове результат вычислился и был отброшен. Во втором мы записали возвращённое число в `health`. Метод не обязан менять внешний мир, чтобы приносить пользу.

## Контракт метода

Для `restoreHealth` договоримся: здоровье от нуля до максимума, лечение неотрицательное, числа небольшие. Результат не превышает максимум. Для отрицательного лечения или переполняющихся чисел этот учебный метод не предназначен. Указывать ожидания полезнее, чем называть любую короткую формулу универсальной.

Аналогично вынесем случайное число:

```java
static int randomBetween(int min, int max) {
    return min + (int) (Math.random() * (max - min + 1));
}
```

Это **объявление метода**: помести его внутри `Main`, рядом с `main`, а не внутрь `main`. Контракт тот же, что раньше: небольшие неотрицательные границы, `min <= max`. Вызов `randomBetween(12, 18)` заменит знакомую формулу атаки.

## return завершает текущий метод

Метод, возвращающий значение, должен вернуть его на каждом пути, который может нормально закончиться. В `void`-методе можно написать `return;` без значения, чтобы завершить его раньше.

Для ввода сделаем `static String readAction(Scanner scanner)`. Внутри можно повторять запрос через `while (true)` до допустимой команды, а затем возвращать её. Конец ввода возвращает `"0"`. Здесь `return` выйдет из `readAction`; игровой `main` продолжит работу с результатом.

В Java все аргументы передаются по значению. Для `Scanner` копируется ссылка на тот же объект, поэтому чтение через параметр действительно продвигает общий поток ввода. Это не передача самой переменной «по ссылке». Глубже в объекты сейчас не погружаемся.

## Постоянные настройки

```java
final int MAX_HEALTH = 100;
final int TOTAL_FIGHTS = 3;
System.out.println(MAX_HEALTH);
System.out.println(TOTAL_FIGHTS);
```

`final` запрещает повторное присваивание этой переменной после инициализации. Имена в верхнем регистре — соглашение для констант. Здоровье героя менять нужно, поэтому `heroHealth` остаётся обычной переменной.

Практика: проверь лечение 50 + 20 → 70, 95 + 20 → 100, 100 + 0 → 100. Удали присваивание результата в `main` и объясни, почему здоровье не меняется.
