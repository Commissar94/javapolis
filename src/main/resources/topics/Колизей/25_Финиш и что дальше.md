# Арена работает. Что ты теперь умеешь?

В начале курса герой умел только называться Спартаком. Теперь у него есть три соперника, выбор действий, ограниченные ресурсы и возможность проиграть из-за собственных решений. Для первого проекта — вполне насыщенная биография.

Но главный результат не в гладиаторе. Ты прошёл путь от отдельных значений до программы, в которой несколько правил работают вместе.

## Проверь понимание

Попробуй ответить без просмотра решения:

1. Почему имя хранится в `String`, а здоровье — в `int`?
2. Чем `=` отличается от `==`, а сравнение строк — от сравнения чисел?
3. Зачем после вычитания брони ограничивать урон единицей?
4. Почему условие `while` само не отменяет ответ уже поверженного врага?
5. Где должны объявляться зелья, чтобы их было два на весь турнир?
6. Чем `break`, `continue` и `return` отличаются по месту продолжения программы?
7. Почему вызов `restoreHealth` без присваивания результата не лечит героя?
8. Зачем проверять выход до начисления победы?

Если на вопрос не находится ответ, вернись к соответствующей главе и воспроизведи маленький пример. Не нужно перечитывать всё подряд с чувством вины.

## Два самостоятельных улучшения

Выбери одно, реализуй и проверь крайние случаи.

**Монеты за победу.** Добавь `gold = 0` до турнира, начисляй 10 монет только за завершённую победу. За три победы — 30, за выход в первом бою — 0, за выход во втором после первой победы — 10. Выведи итог. Это возвращает в игру золото из паспорта первого этапа.

**Настраиваемый отдых.** Вынеси величину отдыха в `final int REST_HEAL = 25` и используй её при восстановлении. Проверь 0 и 100: в первом случае отдых ничего не лечит, во втором не превышает максимальное здоровье. Сами зелья по-прежнему лечат на 20.

Не добавляй оба изменения разом: отдельная рабочая версия после каждого поможет понять причину ошибки. А затем поменяй реплики, имена и баланс. Вот тут авторский стиль можно выпускать на арену без ограничений.

## Что оставим следующему Колизею

Сейчас один файл и несколько переменных помогают увидеть всю логику. Когда появятся разные бойцы, оружие и инвентарь, понадобится учиться представлять их объектами и хранить наборы данных. Это уже естественный повод для классов, ООП и коллекций. Многопоточность и другие сложные темы в этот начальный курс не входят.

## На что опирается теория

Языковые правила сверены с Java SE 21. Старые Oracle Tutorials полезны для базового синтаксиса, но написаны для JDK 8; если в будущем появятся расхождения, ориентируйся на актуальную спецификацию и API выбранной версии.

- [JLS 21: литералы](https://docs.oracle.com/javase/specs/jls/se21/html/jls-3.html#jls-3.10), [типы и переменные](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html).
- [JLS 21: условия и циклы](https://docs.oracle.com/javase/specs/jls/se21/html/jls-14.html), [операторы и выражения](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html).
- [API: Math](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Math.html), [String](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/String.html), [Scanner](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Scanner.html).
- [Oracle: методы](https://docs.oracle.com/javase/tutorial/java/javaOO/methods.html) и [передача аргументов](https://docs.oracle.com/javase/tutorial/java/javaOO/arguments.html).

Правила брони, зелий и отдыха — наш игровой дизайн. Они не следуют из документации Java, зато используют её возможности. Ты теперь умеешь менять их осмысленно. Погнали делать следующий проект — когда этот действительно работает.
