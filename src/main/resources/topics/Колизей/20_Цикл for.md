# for: в расписании три боя

`while` удобен для «пока оба живы». Когда заранее известно число повторений, часто понятнее `for`.

```java
for (int fight = 1; fight <= 3; fight++) {
    System.out.println("Бой: " + fight);
}
```

В круглых скобках три части через точку с запятой:

1. `int fight = 1` — выполняется один раз перед началом.
2. `fight <= 3` — проверяется перед каждым проходом.
3. `fight++` — выполняется после обычного завершения тела, затем снова проверяется условие.

Получим бои 1, 2, 3. При `< 3` их было бы только два. Границы циклов заслуживают отдельного взгляда: одна черта в `<=` может отменить финал турнира.

## Цикл внутри цикла

```java
for (int fight = 1; fight <= 2; fight++) {
    int round = 0;
    while (round < 2) {
        round++;
        System.out.println("Бой " + fight + ", раунд " + round);
    }
}
```

Будут четыре строки: два раунда первого боя, затем два второго. Внешний цикл отвечает за бои, внутренний — за ходы одного боя. Вложенность здесь не новая магия, а две обычные инструкции на разных уровнях.

`break` из внутреннего `while` **не завершает внешний `for`**. После окончания боя снаружи нужно проверить, вышел ли игрок или проиграл ли герой, и при необходимости выйти уже из `for`.

У `continue` в `for` есть отличие: после него выполняется часть обновления (`fight++`), затем проверяется условие. В `while` отдельной автоматической части обновления нет.

## Где хранить состояние

Здоровье героя, зелья, общее число ходов и победы создаём до `for`: они относятся ко всему турниру. Здоровье и броню нового врага создаём в теле `for`, до `while`: на каждый бой появятся новые начальные значения. Временную защиту — внутри `while`, на каждый ход заново.

Если положить `int potions = 2` внутрь `for`, герой получит два новых зелья перед каждым боем. Это допустимое правило другой игры, но наш турнир так не работает.

Практика: выведи три боя и по два тренировочных раунда в каждом. Проверь шесть строк. Затем добавь `break` после первого раунда и объясни, почему получишь три строки, а не одну.
