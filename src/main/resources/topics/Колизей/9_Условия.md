# if: иногда удар нужно отменить

Сейчас мы умеем получить `true` или `false`. Осталось сделать так, чтобы программа на это реагировала.

```java
int damage = -7;
if (damage < 1) {
    damage = 1;
}
System.out.println(damage); // 1
```

Если условие в круглых скобках истинно, выполняется блок в фигурных. Если ложно — блок пропускается. В условии нужен `boolean`; целое число само по себе условием в Java не становится.

Так мы вводим **правило игры**: успешный удар всегда наносит хотя бы один урон. Java не требует именно такого правила. Его придумали мы, чтобы два бронированных бойца не стояли вечно и не вежливо звенели мечами.

## Вариант «иначе»

```java
int enemyHealth = 0;
if (enemyHealth > 0) {
    System.out.println("Противник отвечает.");
} else {
    System.out.println("Противник повержен.");
}
```

Выполнится ровно один из двух блоков. Если вариантов больше, добавляй `else if`:

```java
int health = 25;
if (health == 0) {
    System.out.println("Поражение.");
} else if (health < 30) {
    System.out.println("Пора подумать о лечении.");
} else {
    System.out.println("Можно продолжать.");
}
```

Проверки идут сверху вниз до первого подходящего случая. Два отдельных `if` — другая конструкция: они проверяются независимо и могут выполниться оба.

## Порядок — часть правил

После удара сначала обновляем здоровье врага, потом проверяем, может ли он ответить. Если проверять старое здоровье, поверженный враг получит лишний удар. В некоторых играх это фича. В нашей — баг.

Если здоровье стало отрицательным, приравняем его к нулю:

```java
int health = -8;
if (health < 0) {
    health = 0;
}
System.out.println(health);
```

Всегда ставь фигурные скобки, даже вокруг одной инструкции. И не ставь `;` сразу после `if (условие)`: тогда условный оператор получит пустую инструкцию, а следующий блок выполнится отдельно.

Практика: для атак 18 и 4 при броне 5 посчитай итоговый урон. Должно получиться 13 и 1. Потом вычти урон из 5 HP и не показывай отрицательное здоровье.
