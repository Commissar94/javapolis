# Урон: сегодня меч лёг удачно

Фиксированный урон удобен для проверки. Но одинаковый бой быстро превращается в расписание электрички. Добавим небольшой разброс.

`Math.random()` возвращает псевдослучайное `double` от 0 включительно до 1 **не включительно**. Скобки означают вызов готового метода. Детали создания собственных методов будут перед пятым этапом.

```java
int attack = 12 + (int) (Math.random() * 7);
System.out.println(attack);
```

Здесь получится одно из целых чисел от 12 до 18 включительно.

## Откуда взялась семёрка

1. `Math.random()` даёт число в диапазоне `[0, 1)`.
2. Для этого небольшого диапазона умножение на 7 даёт значение от 0 до 7, не включая 7.
3. `(int)` отбрасывает дробную часть: остаётся одно из `0, 1, 2, 3, 4, 5, 6`.
4. Прибавляем 12: получаем `12, 13, 14, 15, 16, 17, 18`.

В диапазоне 12–18 **семь** целых чисел. Обе границы входят. Для наших маленьких неотрицательных диапазонов используем:

```java
int min = 8;
int max = 12;
int value = min + (int) (Math.random() * (max - min + 1));
System.out.println(value);
```

Условия этой формулы в курсе: `min <= max`, границы небольшие, разность и сумма помещаются в `int`. Это учебный способ для игрового урона, а не универсальная утилита для любых границ или защиты паролей.

## Ловушка со скобками

`(int) Math.random() * 7` сначала превращает значение меньше единицы в ноль, а потом умножает ноль. Разброс получится потрясающий: всегда ноль. Поэтому преобразование должно охватывать результат умножения: `(int) (Math.random() * 7)`.

Генерируй атаку **внутри цикла**, иначе одно случайное число будет выбрано перед боем и повторится на каждом ходу. После генерации применяй броню точно так же, как на втором этапе.

## Как это проверять

Два запуска могут дать одинаковые числа — случайность не обязана выглядеть разнообразно по заказу. Проверяем границы и правила, а не обещание «каждый раз всё другое». Для пошаговой отладки временно замени случайную атаку на 12. После проверки верни генератор.

Практика: выведи 20 значений от 8 до 12 с помощью `while`. Значений вне диапазона быть не должно. Отсутствие одной из границ в двадцати попытках само по себе не ошибка.
