# Колизей 1 — курс для начинающих

Полный курс: **25 глав, 5 практических этапов**, одна консольная игра от карточки героя до турнира из трёх боёв. Главы находятся в `src/main/resources/topics/Колизей` и автоматически включаются в существующий раздел университета.

## Последовательность

| Этап | Главы | Результат |
|---|---|---|
| 1 | 1–6 | Паспорт: типы, переменные, вывод |
| 2 | 7–11 | Один обмен ударами: арифметика, логика, условия, отладка |
| 3 | 12–15 | Автоматический бой: while, случайный урон, break/continue |
| 4 | 16–19 | Управляемый бой: Scanner, строки, атака, защита, лечение |
| 5 | 20–25 | Турнир: for, методы, параметры, return, общее состояние |

Нужны JDK 21 и IDE. Ученику не требуются Python, Maven, Docker или знание Git. Массивы (кроме готовой сигнатуры `main`), коллекции, проектирование классов, наследование, исключения как самостоятельная тема и многопоточность не преподаются. Готовые `String`, `Scanner`, `Math` используются с объяснением нужных операций.

Практика выполняется в IDE. Это **не интеграция пяти проектов с браузерным judge**: существующая задача `sum` не принимает эти `Main.java`. В каждой практической главе есть требования, контрольные сценарии, скрытая подсказка, полное решение и критерий готовности. Все решения доступны также отдельно в `solutions/stage-01` … `stage-05`.

## Запустить отдельный этап

Например, из корня репозитория:

```sh
cd courses/coliseum/solutions/stage-05
javac -encoding UTF-8 Main.java
java Main
```

Вводи имя, затем команды с Enter: `1` — атака, `2` — осторожный удар, `3` — лечение, `0` — выход. Каждый этап — отдельная программа с собственным `Main`; не компилируй все пять в один пакет одновременно.

## Для автора: как редактировать и проверять

1. Главы — обычные Markdown-файлы в формате существующего `TopicService`. Не меняй пути первых трёх глав: к ним могут быть привязаны прогресс и комментарии.
2. `course.json` хранит порядок, названия и привязку к этапам. Названия файлов имеют числовой префикс. Сортировка тем учитывает число, поэтому 10-я глава идёт после 9-й.
3. При изменении эталона обнови и `solutions/stage-XX/Main.java`, и его кодовый блок в практической главе. Проверка обнаружит расхождение.
4. Сохраняй зависимость «объяснение → использование»: синтаксис должен появляться в теории до практики.
5. Ссылки на Oracle размещены в соответствующих главах. Спецификация и API — Java SE 21; старые Oracle Tutorials используются только для неизменившихся основ.

Из корня репозитория запусти:

```sh
python3 courses/coliseum/verify.py
```

Проверка требует Python 3.9+ и JDK 17+ (целевой JDK курса — 21). Она компилирует 40 Java-блоков с совместимостью `--release 17`, проверяет конкретный вывод 31 примера, ожидаемый отказ намеренно ошибочного фрагмента, соответствие встроенных эталонов, ссылки и изображения. Затем запускает пять этапов и контрольные сценарии: броня выше атаки, точный/избыточный урон, смерть, неверный ввод, EOF, лечение, сброс защиты, общие зелья, отдых и завершение турнира.

Случайность проверяется двумя способами: обычные запуски с проверкой диапазонов и временные детерминированные копии, не изменяющие опубликованные решения. Все компилируемые файлы и результаты находятся во временной папке, удаляемой после проверки.

GitHub Actions (`coliseum-course.yml`) запускает эту проверку на JDK 21. Сам факт наличия workflow не означает, что он уже запускался на GitHub.

`ColiseumCourseTest` дополнительно проверяет реальный `TopicService`: порядок глав, сохранение старых путей, рендеринг всех 25 глав и скрытые решения. Это целевой JUnit 5 тест; для Maven нужен Surefire с поддержкой JUnit 5. Полный запуск платформы с PostgreSQL и Docker judge — отдельная проверка, не заменяемая тестами курса.

## Учебные решения

Минимальный урон 1, максимум HP 100, два зелья, отдых +25 между боями и числовые команды — намеренно простые правила. В финале состояние турнира остаётся в `main`, а в методы выносятся небольшие операции. Это позволяет закончить проект до введения ООП.

Фактические исправления старой теории: `null` не присваивается примитивам; `String` не примитив; `char` — элемент UTF-16, а не любой видимый символ; дробные типы поддерживают отрицательные значения; локальные переменные требуют инициализации; диапазоны случайного урона включают обе заданные целые границы.
